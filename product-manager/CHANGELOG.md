# Changelog

## 1.1.2 — 标准流程、移除网页知识库与逻辑一致性修复（2026-10-06）

- 新增 `workflows/standard-flow.md`：正向（F1 问题 → F11 复盘，每步写明模式、产物和过关条件）与反向（R1 锁定 → R6 收束，分自有项目和竞品两种对象），并规定反向结论从正向哪一步接入。原 `idea-to-mvp` 与 `feature-development` 两个重叠的正向流程并入其中。
- 移除可选网页知识库（`scripts/pm_kb.py`、`references/knowledge-base-ops.md`、`references/knowledge-sources.json`、`knowledge-ops` 模式及其测试）。实测 8 个白名单来源中只有 1 个抓到实质正文，其余多为目录页或落地页；且易变事实本就需要实时核对一手页面。`living-sources.md` 保留为来源入口清单，需要时直接打开核对。
- 正向主线改为先定成功指标、评审通过后再交接；AI 0→1 先收集真实任务样本再选架构，不默认加入 RAG。
- 生命周期写明进入/退出条件的含义，区分 VALIDATION（设计验证）与 MVP（执行验证）。
- 统一词表：模式内细分证据标签与基础标签的对应关系写入 Foundations；能力状态以 project-reality 为唯一词表（`已实现未部署` 改为 `已实现` + 单独记录部署）；决策记录增加 `REJECTED`、`STOPPED`、`SUPERSEDED` 终止状态。
- SKILL.md 增加工作流索引；Slop Test 中能当场修正的问题先修正再交付。PRD 模板修正重复章节编号并补 Offline 状态；assess 接入 problem-brief 模板。
- 冻结的八个行为案例与评分标准不变，本次不宣称模型盲测通过。

### 随附文档更新（2026-10-02）

- 增加 Claude Code 个人／项目目录安装、Claude 网页／桌面端 ZIP 上传和 WorkBuddy 本地技能包导入说明；补充调用差异、包结构、验证与排错。
- 同步主仓库与说明仓库的安装导航和手册；运行版本仍为 v1.1.1，本项不构成跨宿主任务验收。

## 1.1.1 — 知识库内容校验与路由修复（2026-10-01）

- 重写公开仓库专业介绍、安装升级和详细使用说明，增加合成电商 AI 客服演练；安装目录核对当前官方文档，独立说明仓库同步公开源码导航。

- 拒收返回 HTTP 200 的已知访问拦截、验证与密码登录页面，保留最新有效快照；增加离线回归，验证错误记录、历史可检索性及正常文档不会因提到错误术语而被拒收。
- 将 AI 架构固定阶梯改为按任务缺口选择和组合能力，不要求采用 RAG 或 Agent 后才能使用 Tools 或 Fine-tuning。
- 接入 Foundations、Frameworks 和 AI Product Craft 的按需知识入口；术语以 glossary 为准，terms 文件保留旧引用兼容。
- 与 product-manager-skills 明确主工作流和专项资料分工，保留自动发现与用户显式选择。
- 校验器检查包内版本一致性，行为评分表从当前 Manifest 读取 Skill 版本；冻结的八个行为案例与评分标准不变，本次不宣称模型盲测通过。

## 1.1.0 — 项目反推拆解（2026-09-27）

- 新增 `reverse-decompose`：从已有代码/产品仓库重建可追溯的现状、用户任务、能力和模块依赖，再把可能的产品意图与真实证据分开。
- 新增按需的项目反推拆解图及行为回归案例；静态代码、测试、部署和真实用户验收不再被混写成同一状态。
- 此次为兼容性新增，不迁移或重抓包外知识库，不自动改写项目记录；需要正式优先级、PRD 或上线判断时仍转入现有模式。

## 1.0.0 — 首个正式版（2026-09-26）

- 将开发编号 2.5.0 的完整 Product Manager OS 定为正式 v1.0.0；这是版本定版，不是功能回退。
- 包含产品发现与决策、用户研究、竞品情报、定价、产品体验、跨端交付、AI Eval、单位经济、持续复查，以及受控来源同步与本地知识库备份。
- 不迁移、不清空或重抓已有知识库；已配置的每周同步自动化保持原计划。Skill 安装本身仍不会启动后台任务。
- 首次公开发布 Skill 源码、模板、测试与专业指南，采用 Apache-2.0 许可；匿名化示例，不发布运行时知识库、网页快照、备份和项目私有记录。
- 下列 2.x 与初期 1.0.0 仅为正式定版前的开发历史编号，不构成正式版的升级顺序。
