# Changelog

## 1.1.0 — 项目反推拆解（2026-09-27）

- 新增 `reverse-decompose`：从已有代码/产品仓库重建可追溯的现状、用户任务、能力和模块依赖，再把可能的产品意图与真实证据分开。
- 新增按需的项目反推拆解图及行为回归案例；静态代码、测试、部署和真实用户验收不再被混写成同一状态。
- 此次为兼容性新增，不迁移或重抓包外知识库，不自动改写项目记录；需要正式优先级、PRD 或上线判断时仍转入现有模式。

## 1.0.0 — 首个正式版（2026-09-26）

- 将开发编号 2.5.0 的完整 Product Manager OS 定为正式 v1.0.0；这是版本定版，不是功能回退。
- 包含产品发现与决策、用户研究、竞品情报、定价、产品体验、跨端交付、AI Eval、单位经济、持续复查，以及受控来源同步与本地知识库备份。
- 不迁移、不清空或重抓已有知识库；已配置的每周同步自动化保持原计划。Skill 安装本身仍不会启动后台任务。
- 首次公开发布 Skill 源码、模板、测试与专业指南，采用 Apache-2.0 许可；匿名化示例，不发布运行时知识库、网页快照、备份和项目私有记录。
- 下列 2.x 与初期 1.0.0 仅为正式定版前的开发历史编号，不构成正式版的升级顺序。

## 开发历史（旧编号，仅供追溯）

### 旧编号 2.5.0

- 增加精确 URL 白名单的公开来源增量同步，遵守 robots.txt，并为外部证据记录抓取时间、响应标识和内容哈希；不爬取登录页或自动扩展链接。
- 增加可检索的本地 SQLite 知识库及独立、可校验的备份与恢复流程，数据目录由使用者显式指定，不随 Skill 升级覆盖。
- 将来源缓存纳入证据治理：离线快照不冒充当前事实，不采纳网页内指令，不自动写入项目决策记录。
- 更新运行手册、README、安装说明、包校验与版本；周期抓取由外部自动化单独配置，安装 Skill 本身不会启动后台任务。

### 旧编号 2.4.0

- 增加持续产品工作闭环：从当前证据与项目状态出发，连接决策、执行、测量和复查；项目记录默认只读，写回需在授权范围内。
- 简化跨模式路由，按本轮必须支持的决定选择一个主模式，并让重要产物的深度与风险相称。
- 根据一次独立延续任务试运行收紧按需加载，避免沿引用链读取与本轮无关的模板。
- 修复 AI Eval 模板污染，补充可重复的行为回归与包校验。
- 强化项目上下文、证据来源和决策日志的版本感知与复查机制。

### 旧编号 2.3.1

- 新增按需加载的动态知识来源目录，涵盖用户研究、商业模式与定价、AI Eval、成本、风险及行业趋势。
- 为外部资料规定入口核验、观察日期、来源层级和适用边界；不把来源链接误写成自动同步知识库。
- 更新 README、来源说明、包校验及版本号。

### 旧编号 2.3.0

- 新增 `delivery-os`，面向已有产品的多版本、多角色、跨端交付判断；不以页面数量定义“完整”。
- 新增项目现实快照、角色任务权限地图及跨端验收三个按需模板，显式区分部署、自动测试、真实验收和正式运营。
- 将现状核查接入 Skill 路由与版本范围决策，避免把旧系统、演示版和新产品能力混写。
- 根据已有产品的跨版本工作台案例增加交付判断回归审计；保留竞品、研究、定价、AI Eval、成本控制等既有能力。仓库内的示例已匿名化。
- 更新 README、Manifest 与校验器。
