# Skill Improvement Loop｜Product Manager OS 自身迭代

此流程只改进 Skill 的方法、路由、模板和工具；项目产品的观察与复盘仍走 `workflows/continuous-product-loop.md`。无需每次调用都启动。只有出现真实坏例、重复摩擦或明确的维护请求时启动；用户只要建议时止于提案。

| 门 | 必须留下的证据 | 不通过时 |
|---|---|---|
| 1. Intake | 实际任务、当时输入/输出、版本/环境、预期行为、影响；原始资料位置与权限 | 信息不足则登记为待复现，不猜测原因 |
| 2. Triage | Skill/模型/工具/输入/外部原因的主因假设、替代解释、严重度、Owner | 非 Skill 根因转交相应 Owner，不为了改而改 |
| 3. Candidate | 最小变更、可检验的行为预期、受影响模式、潜在回归、回滚方案 | 没有可观察验收标准则先补测试 |
| 4. Regression | 同一冻结夹具的旧/新原始回答、人工评分、逐项差异；记录并人工核对模型构建、采样、工具权限与来源时点；新增案例两版都重跑 | 候选版关键项失败、条件不明或未解释的回归则修订/暂缓 |
| 5. Release | 维护者对具体提交的批准、隐私与许可检查、版本号、README/CHANGELOG/升级说明、包与工具测试 | 未批准不能自动安装、推送或发布 |
| 6. Observe | 发布后失误复发、任务完成质量与成本的观察窗口及复查日期 | 结论为待验证；严重回归提出受控回滚 |

最小可执行路径：先在用户指定的包外私有目录填 `templates/skill-badcase.md`，仅把已脱敏的可复现内容转为回归题；再填 `templates/skill-change-proposal.md`。评测协议见 `tests/behavior/README.md`。比较命令在 Skill 根目录执行：

```text
python tests/behavior/score.py --compare <旧版评分.json> <候选版评分.json>
```

脚本只读取评分及原始回答并输出差异，仅能机械核对相同夹具哈希和模型标识；无法证明服务端模型构建、采样、工具权限和在线来源完全一致。原始资料、评分历史和审批记录默认不进入公开 Skill 包。它的通过状态**不是发布授权**：人工评审仍须核对运行条件、实际回答、风险和私有资料边界。不能为了提升分数修改同一轮的冻结问题或评分标准；若测试集需要更新，建立新版本夹具并保留旧版结果。
