# Standard Flow｜正向与反向标准流程

先判断方向：**手里还没有产品，从问题出发 → 正向；已经有一个产品（自己的仓库、接手的项目、竞品或标杆）要先弄清它是什么 → 反向**。反向的终点是一个决定，从下文规定的那一步接入正向；正向上线后的产品，做下个版本前可以再走一次反向核对现状。

每步只加载该步的模式。简单任务可以只走相关几步，但不跳过过关条件；不满足时停在当前步，说明缺什么。

## 正向：从问题到复盘

| 步 | 阶段 | 模式 | 产物 | 过关条件 |
|---|---|---|---|---|
| F1 | IDEA | `assess` | 一句话问题、事实/假设、四类风险 | 用户和场景具体，问题里没有夹带方案 |
| F2 | DISCOVERY | `discover`（需要看竞品时加 `competitive-intelligence`） | 研究计划与证据表 | 有过去真实行为的证据，说得出当前替代方案 |
| F3 | VALIDATION | `mvp` | 最危险假设、最低成本验证设计、成功/停止门槛 | 门槛在验证开始前写定 |
| F4 | MVP | `mvp`、`metrics` | 验证结果 | 按事先门槛判定：进入 Build / 再验证 / 暂停 |
| F5 | BUILD 准备 | `prioritize` + `metrics` | 版本范围（做/暂缓/不做）、主指标、基准、护栏 | 每项有证据来源，砍掉的写明原因 |
| F6 | BUILD 准备 | `prd`；AI 功能用 `ai-prd` + `eval`；流程不清先 `experience` | PRD / AI PRD、Eval Spec | 有 Non-goals、异常状态和验收标准 |
| F7 | BUILD 准备 | `review` | 评审结论与修复 | 达到 SOLID 以上，根本问题修完 |
| F8 | BUILD | `handoff` | 研发交接 | 工程和测试知道“什么算对” |
| F9 | TEST | — | 测试与验收记录 | 验收全过，埋点与 Eval 可运行 |
| F10 | LAUNCH | `launch` | 灰度计划与回滚阈值 | 每一级放量有进入/退出门槛 |
| F11 | MEASURE → ITERATE | `retro` | 预测与实际的对照、更新后的假设 | 形成继续/扩大/缩小/回滚/停止的决定 |

- 问题还没验证的想法从 F1 开始；需求已有行为证据的常规功能从 F5 开始。
- AI 产品走同一主线，F3–F10 的细节按 `workflows/ai-product-0-to-1.md`；Agent 按 `workflows/agent-development.md`。
- 阶段的进入/退出定义见 `workflows/lifecycle.md`。
- F11 的决定回到 F1（新问题）、F5（下个版本），或转反向（现状已经和文档对不上）。

## 反向：从已有产品到决定

| 步 | 模式 | 自有项目（仓库、接手的系统） | 竞品／标杆（公开网页、App、接口） | 过关条件 |
|---|---|---|---|---|
| R1 锁定 | `reverse-decompose` | 本轮决定；仓库、分支/提交、环境、检查日期 | 本轮决定；对象与版本、观察日期；只用公开可见信息 | 决定和检查边界写清 |
| R2 取证 | `reverse-decompose` | 入口 → 角色/权限 → 任务 → 对象 → 模块 → 数据，附文件:行 | 页面/路由 → 功能 → 价目与规则原文 → 接口，附 URL 与日期 | 关键结论都能追到来源 |
| R3 分状态 | `reverse-decompose` | 按 `references/project-reality.md` 状态词表逐项记录（已实现 ≠ 已部署 ≠ 已验收） | 只能证明“公开可见”，不推断内部实现、规模或效果 | 没把代码或宣传当成已验证效果 |
| R4 反推 | `reverse-decompose` / `competitive-intelligence` | 可能的用户、任务与业务规则，标 `[推断]` 并给替代解释 | 目标用户、钱怎么流、增长机制，标 `[推断]` | 每条推断有最小核验方式 |
| R5 找差距 | 自有：`delivery-os`；竞品：`competitive-intelligence` | 断链、重复实现、权限/数据/失败路径缺口 | 值得学的、不该学的（合规、伦理）、对方弱点 | 按影响排序，不把每个目录都变成待办 |
| R6 收束 | — | 一个决定：先补哪条证据或修哪条任务链 | 一个决定：做 / 暂缓 / 不做，加止损条件 | 写明 Owner、下一动作、复查触发条件 |

产物：自有项目用 `templates/project-reverse-map.md`，竞品用 `templates/competitive-intelligence.md`。全程只读：不运行不可信脚本、不登录、不改项目文件。

## 反向接回正向

| 反向得出的决定 | 接入 |
|---|---|
| 竞品验证了需求，要做自己的版本 | F1：竞品有不等于你的用户需要，证据要换成自己用户的 |
| 已有项目方向成立，要补齐或改版 | F5；跨多版本、多角色时先用 `delivery-os` |
| 已有项目只差上线判断 | F10 |
| 现状和要解决的问题都不清楚 | F1 / F2 |
