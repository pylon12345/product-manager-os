# v2.2 场景审计

审计方式：使用真实工作语气的请求检查入口路由、阶段门禁、必要证据和输出边界。此表是静态规则审计；尚未进行独立模型盲测，不把规则覆盖视为行为通过。

| 请求 | 应选择的主模式 | 阶段与关键门禁 | 期待产物 | v2.1 发现 |
|---|---|---|---|---|
| “老板要做 AI 客服，明天给 PRD” | `assess`；信息足够后 `ai-prd` | IDEA；用户问题和真实场景未证实时只能给草稿或验证计划 | 问题简报、关键假设、下一步证据 | 有门禁，需防止机械阻塞草稿 |
| “做一轮流失用户访谈，判断为何取消” | `research-ops` | DISCOVERY；招募与隐私、反例 | 研究计划与综合表 | 已覆盖 |
| “竞品推出免费版，我们也要不要做” | `competitive-intelligence`，必要时 `pricing` | 比较同一细分和工作任务；验证最新价格 | 战略回应与触发条件 | 已覆盖 |
| “12 个需求都说是 P0，帮我排版本” | `prioritize` | 明确目标、资源、依赖；必须有砍项 | 范围决策与取舍 | 已覆盖 |
| “设计 AI 客服处理退款的页面” | `experience`，必要时 `ai-prd` | 用户流程、授权、错误与人工接管 | 体验简报与设计交接 | v2.1 无专门路由 |
| “这张截图的 UI 哪里不好” | 产品设计审查；PM 可补产品任务判断 | 需要实际图像证据 | 具体位置、影响与改法 | v2.1 容易误路由到 PRD/review |
| “AI 自动回复上线前怎么验收” | `eval` + `launch` | TEST；质量切片、安全、成本、回滚 | Eval Spec 与上线门禁 | 已覆盖，需结合用户体验恢复路径 |
| “调用量翻倍，模型费用超预算” | `ai-economics` | MEASURE；成功任务成本、p95、重试与重度用户 | 成本驱动模型与优化次序 | 已覆盖 |
| “调价后转化下降但收入升了，怎么办” | `pricing` + `metrics` | MEASURE；分群、折扣、流失和毛利 | 决策与复查阈值 | 已覆盖 |
| “上线两周数据不好，是否继续” | `retro` + `metrics` | MEASURE；检查埋点与原始预测 | 继续/缩小/回滚/停止 | 已覆盖 |

## 修订决定

- 增加 `experience` 路由及简报模板，覆盖产品侧体验判断。
- 视觉稿、交互原型、像素级 UI 与现有界面图像审查由设计工作流完成。
- 给 PRD、AI PRD 与研发交接增加关键体验状态和可用性验证连接。
- 修复 README 的目录清单与安装描述漂移。
