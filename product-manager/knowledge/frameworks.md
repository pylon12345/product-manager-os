# Framework Selection Guide

| 场景 | 优先框架 | 适合解决什么 | 常见误区 |
|---|---|---|---|
| 访谈 | Mom Test 思路 | 从过去行为取证 | 问“你会不会买” |
| 用户任务 | JTBD | 理解用户要取得的进展 | 把人口属性当需求 |
| 机会拆解 | Opportunity Solution Tree | Outcome→机会→方案→实验 | 直接从目标跳到功能 |
| 优先级 | RICE / ICE | 形成可讨论的相对排序 | 伪精确、分数无证据 |
| 版本范围 | MoSCoW | Must/Should/Could/Not now | 所有需求都变 Must |
| 时间盒 | Shape Up Appetite | 固定时间，砍 Scope | 用估时冒充承诺 |
| Roadmap | Now/Next/Later | 表达不确定性 | 把 Later 写成精确日期 |
| 定位 | Positioning | 明确为谁、替代谁、为什么选你 | 只写口号 |
| 指标 | North Star + Inputs + Guardrails | 连接价值与行为 | 只看 DAU |
| 实验 | 假设→干预→指标→门槛 | 降低决策不确定性 | A/B 测所有问题 |
| 产品体验 | 用户任务闭环 + 信息结构 + 关键状态 + 可用性测试 | 把问题转为可完成、可恢复的体验 | 把视觉稿当作体验已经验证 |
| 竞品情报 | Competitive set + Evidence hierarchy + Win/Loss | 形成定位与竞争回应 | 只做功能矩阵 |
| 研究运营 | Decision brief + Mixed methods + Evidence table | 把研究连接到决策 | 用访谈数代替采样逻辑 |
| 定价 | Value metric + Packaging + Scenario model | 连接价值、购买和毛利 | 复制竞品价格或成本加成 |
| AI Eval | Eval tree + Slices + Regression gate | 决定是否可发布 | 只看单一平均分 |
| AI 经济 | Driver model + Cost per successful task | 控制成本并保护质量 | 只优化 Token 单价 |

原则：框架是思考工具，不是结论生成器。
