# Mode: assess

目标：判断“问题是否值得继续投入”，而不是判断“功能写得好不好”。

## 评估框架
1. **Problem**：真实问题是什么？有没有把解决方案偷塞进问题定义？
2. **User**：谁最痛？在什么具体场景？
3. **Evidence**：过去真实行为、数据、访谈、工单、销售信号有哪些？
4. **Alternatives**：用户现在怎么解决？为什么会换？
5. **Value**：频率、强度、时间/金钱/风险代价。
6. **Viability**：商业、运营、合规是否成立？
7. **Feasibility**：技术依赖与最大未知数。
8. **Kill / Revisit**：出现什么证据应停止、缩小或改方向？

## 输出
- 一句话问题定义
- 事实 / 假设 / 待验证
- 四类风险
- 最小验证动作
- 建议阶段：继续 Discovery / 进入 MVP / 暂停

复杂评估可用 `templates/problem-brief.md` 记录。

不要为了显得精确而制造伪评分。若使用评分，必须说明评分依据。
