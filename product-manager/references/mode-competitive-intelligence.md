# Mode: competitive-intelligence

目标：把市场与竞品信息转化为定位、路线图、销售或进入市场决策，不做没有决策用途的功能表。

## 1. 先定研究边界

- 决策：定位、进入市场、Roadmap、定价、销售支持还是合作/收购？
- 范围：目标细分、Buyer、JTBD、地域、时间窗口。
- 截止日期：价格、功能、管理层和策略等时效信息必须注明观察日期。

## 2. 竞争集合

- **Direct**：同一用户、同一核心任务。
- **Indirect**：不同产品形态，完成同一任务。
- **Substitute**：表格、人工、外包、自建或不处理。
- **Emerging**：平台、技术、法规或渠道变化带来的潜在进入者。

## 3. 证据等级

1. 自有一手证据：Win/Loss、流失、试用、客服、销售录音、使用行为。
2. 竞品一手来源：官网、产品、价格页、文档、Release Notes、招聘、财报。
3. 独立来源：用户评论、社区、分析报告、合作伙伴。
4. 推断：必须写 `[推断]` 与验证方式。

每条关键发现记录 Source、Date、Segment relevance、Confidence。没有公开信息不等于竞品没有该能力。

## 4. 分析维度

- 目标细分、Buyer 和购买触发
- 类别、承诺结果、Proof
- 工作流覆盖与切换成本
- 获客/分发优势
- 数据、AI、信任、安全、合规
- 价格度量、Packaging、合同与服务
- 明确弱点、约束与可能回应

区分 `Claimed / Observed / Inferred`。比较维度必须影响购买、留存或战略，不按功能数量评分。

## 5. Win/Loss

按 Segment、Use case、Trigger、Incumbent、Shortlist、Decision criteria、Objection、Outcome 编码。先找重复机制，再看总体比例；样本弱时只输出假设，不伪装普遍规律。

## 6. 战略回应

每个重要发现只能落入一个主要动作：

- Ignore：影响低或可信度低。
- Monitor：写清领先信号与触发阈值。
- Defend：保护高价值位置或留存来源。
- Differentiate：强化影响购买的差异。
- Reposition：调整细分、类别或承诺。
- Partner / Acquire：外部补足比自建更合理。

禁止仅因“竞品有”就复制。需说明目标用户、预期影响、成本、机会成本和验证方式。

## Quality Gate

- 结论可追溯到证据和日期。
- 比较对象处于相同 Segment / JTBD，差异已说明。
- 包含替代方案和“不做”。
- 推荐改变一个明确决策。
- 未知保持未知，推断可证伪。
