# Mode: discover

目标：从用户过去的真实行为中获得证据。

## 原则
- 优先问过去具体发生过什么，少问“你以后会不会用”。
- 赞美不算证据；时间、金钱、数据、流程改变等承诺信号更强。
- 访谈与行为数据互相校验，不把单一口述当结论。

## 常用方法
- JTBD：触发、期望进展、阻力、替代方案。
- 5 Why：仅用于追问原因，不把它机械化成固定五次。
- Opportunity Mapping：Outcome → Opportunity → Solution → Experiment。
- 竞品分析：重点看用户为什么选它、切换成本、定位和工作流，不只做功能矩阵。

## 输出
使用 `templates/discovery-plan.md`，至少包含：研究问题、对象、问题清单、证据标准、综合方式、下一决策。
