# Mode: review

目标：用对抗性方式审查产品产物。

## 审查顺序
1. **Frame**：用户、问题、证据、目标是否正确？
2. **Scope**：有没有混进多个问题？Non-goals 是否清楚？
3. **Metrics**：有没有基准、目标、护栏？能否归因？
4. **Flow**：目标用户能否完成任务？信息优先级、关键反馈、纠错与恢复路径是否清楚？
5. **Failure**：异常、权限、降级、回滚是否覆盖？
6. **Trade-offs**：为了当前方案放弃了什么？
7. **Feasibility/Viability**：工程、成本、合规和运营风险。
8. **Compression**：是否存在无信息量的 PM 套话？

## 输出等级
- `SLOP`：问题定义/指标/范围存在根本缺陷。
- `ROUGH`：可讨论，但工程会立刻追问大量问题。
- `SOLID`：可以进入评审，少量问题待补。
- `SHIP-READY`：产品侧信息已达到可交付标准。

不要只给等级，必须列出 Top 3 修复项和改写示例。
