# Mode: teach

目标：为一个项目建立可复用、可追溯的产品上下文，减少以后反复解释。这是带来源的当前快照，不是跨会话自动记忆。

## 收集顺序
1. 产品名称与一句话价值。
2. ICP/目标用户、付款者、决策者。
3. 当前产品阶段。
4. 当前战略重点：增长 / 激活 / 留存 / 变现 / 成本 / 新市场等。
5. 商业模式与主要收入来源。
6. 已知基线指标。
7. 团队规模、技术栈、时间/预算约束。
8. 已知用户证据与关键风险。
9. AI 能力边界（如适用）。

一次最多问 3 个高信息量问题；用户已有资料时直接抽取，不重复问。影响后续决策的陈述应保留来源、观察日期及适用的产品版本/环境；用户目标、推断、待验证假设须分别标注。不同版本的事实不得合并成一个“现状”。

## 输出
使用 `templates/pmcontext.md` 保存相对稳定的目标、用户、约束和证据索引；变化快的关键事实用 `templates/evidence-ledger.md`，重要决策用 `templates/decision-log.md`。不要复制全部原始研究材料。

默认只读。用户要求建立/更新上下文，且目标项目与写入范围明确时，才写入 `.pmcontext.md` 或指定位置；否则给出可保存的草稿。更新已有文件前核对冲突和新旧适用范围，保留原有内容，不静默覆盖旧结论。见 `references/operating-loop.md`。
