# Project Reality Gate

用于已有产品的改版、迁移、上线或“做完整”请求。目标是获得可追溯的当前状态，不是重写历史文档。

## 快速检查

1. 列出相关产品面：客户端、管理端、API、数据源、身份与权限、运营流程；只列会影响本次决定的部分。
2. 对每项能力记录版本/环境、负责人、证据日期和状态：`设计中`、`已实现`、`已部署`、`自动测试通过`、`真实身份验收通过`、`正式运营`。`已实现` 只表示代码/配置存在，部署与否单独记录。这些状态逐项核实，不能互相推断。本表是能力状态的唯一词表，其他模式和模板沿用。
3. 标注“旧系统专有”“演示数据”“候选版本”“当前正式入口”。有冲突时，以较新的直接证据优先；仍冲突则标 `[待验证]`。
4. 标出跨端关键对象的主数据源、写入口、同步或迁移协议。没有证据时，不宣称数据一致。
5. 对结论注明检查边界：代码/文档检查、HTTP 可达、模拟测试、真机测试、真实用户试点各覆盖什么。

## 决策规则

- “能打开”不等于“能完成任务”；“测试通过”不等于“真实身份验收”；“开发版上传”不等于“正式发布”。
- 已解决的问题要从阻断项中移除；残余边界单独写清，避免沿用过时审计。
- 若项目资料缺失，先给最小现状表和 1–3 个会改变范围或发布决定的问题，不编造系统能力。
- 只在用户授权范围内检查资料。不要为了完成现状表自行登录、改动生产数据或联系真实用户。

需要可交接记录时使用 `templates/system-reality-map.md`。
