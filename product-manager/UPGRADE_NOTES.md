# 版本升级说明

## v1.1.0 → v1.1.1：内容校验与路由修复

- 替换 Skill 包即可使用新的拦截页校验和按任务选择 AI 架构的规则；已知门禁页面不再成为最新快照。
- 不迁移、清空或自动重抓包外知识库，也不更改已配置的同步任务。若旧库已误收门禁页，先核对 `status` 与当前来源，按既有授权重新同步有效页面，或按恢复流程选择经验证的备份；安装修复本身不自动回退数据。
- 两份 PM Skill 保留自动发现：product-manager 承担一般中文任务与连续交付，product-manager-skills 提供专项深挖。显式选择仍优先。

## v1.0.0 → v1.1.0：项目反推拆解

新增 `reverse-decompose` 参考与可选项目反推拆解图，适用于已有代码/产品仓库。它只读重建现状并标出推断与未知；不会改变既有模式或自动写回项目资料。已有 `.pmcontext.md`、证据/决策记录和包外知识库无需迁移。若安装目录有自定义改动，先比较再升级；行为评估新增一个冻结案例，跨版本评分应保留旧夹具与原始结果。

## 正式版 v1.0.0 定版说明

此前的 v2.5.0 是开发迭代编号；现将**同一完整功能集**定为首个正式版 v1.0.0。这是版本与文档定版，不是回退到初期原型。`SKILL.md`、模板、工作流和本地知识库工具继续保留现有能力。

已有 `.pmcontext.md`、研究资料、证据和决策日志无需批量迁移或改写；包外 SQLite 知识库、快照及备份也无需迁移、清空或重新抓取。已配置的每周同步自动化保持原计划。Skill 安装本身仍不会启动后台任务。

## 开发历史（以下均为旧编号，非正式版升级路径）

### 初期原型（旧编号 1.0.0）的主要不足

1. `SKILL.md` 承担太多职责，Router、知识、工作流和模板边界不清。
2. 虽有 100 个术语，但术语更像教材，未真正参与运行时决策。
3. 会写 PRD，但缺少“是否应该写 PRD”的 Evidence Gate。
4. 缺少稳定的项目上下文，跨多轮开发容易重复解释或前后不一致。
5. 产品评审偏检查清单，缺乏对抗性 Review 和明确质量等级。
6. AI 模块有 RAG/Agent/MCP 等概念，但缺少从非 AI 到 Agent 的升级决策链。
7. AI Eval 模板存在，但与 AI PRD、上线 Gate、线上 Badcase 回归没有完全闭环。
8. 缺少决策日志，难以在上线后校准“当时为什么这么决定”。

### 后续开发迭代如何修复

| 初期原型的问题 | 后续开发迭代的改进 |
|---|---|
| 单体 Skill 偏重 | Router + references 按需加载 |
| 缺上下文 | `.pmcontext.md` + `teach` 模式 |
| 容易直接写方案 | Evidence Gate + `assess` / `discover` |
| AI 容易顺着用户 | Critical Review + PM Slop Test |
| 优先级易伪精确 | 要求分数证据、Trade-off、明确砍项 |
| Agent 容易过度设计 | 规则→Workflow→LLM→RAG→Tools→Agent→Fine-tune |
| AI 规格不完整 | 独立 AI PRD + Eval Spec + Failure Mode + HITL |
| 上线后断链 | Decision Log + Launch Gate + Retro |
| 名词占上下文 | 100 术语下沉到 `knowledge/glossary.*` |

### 定位的演进

初期原型更像“产品经理知识与模板包”。

后续开发迭代形成 **AI Product Manager OS**：在真实开发中帮助判断、验证、规格化、评审、上线和复盘；此完整形态现定为正式版 v1.0.0。

### 旧编号 v2.3.x → v2.4.0：持续工作记录

无需迁移或覆盖已有 `.pmcontext.md`、研究资料和决策日志。v2.4 的新模板增加证据 ID、适用版本/环境、观察日期，以及 `PROPOSED / COMMITTED / REVISITED` 决策状态；它们只用于**后续增量记录**。

若旧项目继续推进，先只读核对旧文件：哪些陈述仍适用于当前版本，哪些只是当时假设，哪些已被新证据推翻。只有用户明确授权维护项目记录时，才把新增字段补进目标文件；保留原始决定和历史证据，不批量重写。没有授权时在回复中提供拟议条目。

`tests/behavior/` 提供行为回归案例与人工评分协议。结构校验通过不能解释为模型质量通过；不同 Skill 版本应使用同一冻结案例作对比，并记录模型、日期与原始回答。

### 旧编号 v2.4.0 → v2.5.0：可选本地知识库

项目上下文、证据和决策日志无需迁移。v2.5 新增白名单公开来源同步、离线检索及 SQLite 备份/恢复；安装或升级 Skill 不会自动抓取。首次使用须显式指定数据目录并运行同步；定时更新需要单独配置自动化。数据目录应放在 Skill 包外，升级时保留，具体操作见 `references/knowledge-base-ops.md`。
